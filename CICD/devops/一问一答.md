
# 如何做构建缓存？
构建缓存可分为本地缓存、远端缓存。而缓存类型可分为：构建依赖缓存、docker镜像缓存、官方工具缓存、自定义缓存

以下主要拣取主要的缓存类型进行描述

## 本地缓存
本地缓存只对独享资源支持，因为对于共享资源，即使做好租户隔离，也很难保证资源实际安全，这对大的云服务提供商是无法接受的。

本地缓存通过overlay实现，实现写时复制和读时共享

云上独享资源的本地缓存按照缓存空间大小收费

### 读时共享
以代码缓存为例，每次拉取代码前，都会首先创建upper层作为缓存副本，基于git做代码拉取的增量更新

### 缓存重建
缓存重建的场景基于不通的缓存场景分别处理，主要分为定时重建和key值判断

#### 代码缓存重建（定时重建）
代码缓存场景一般使用于超大代码仓，多仓构建场景(主要为AOSP构建)，整个代码仓可超过100G

因为代码更新场景的不稳定，若团队协作开发，频繁的缓存重建可能预期外的构建异常（git拉取代码冲突、代码内容丢失）

采用定时重建的方式，用户可配置代码缓存预热时间（每日凌晨）

定时预热开启时，单独执行代码拉取步骤，会跳过实际构建和部署步骤，历史缓存即时删除（短期保留备份用于回滚）

#### 构建依赖缓存重建（自动重建）
构建依赖缓存基于语言识别依赖文件（pom.xml\package.json）生成缓存key，基于不同的缓存key进行缓存重建

依赖缓存的缓存重建不会删除历史key的缓存，缓存的删除基于缓存空间大小做LRU淘汰

用户可自定义缓存key，以适配 java module 等场景 和自定义缓存场景

#### 工具缓存与镜像缓存
官方工具缓存由执行插件管理，切不存在并发读写问题，因此直接在本地进行存储

镜像缓存基于docker缓存(--cache-from、--cache-to)

## 远端缓存
远端缓存基于OBS实现，远端缓存主要应用于依赖缓存、镜像缓存

基于不同的缓存key，整个依赖会打包存储于OBS桶中，总的缓存大小做限制
